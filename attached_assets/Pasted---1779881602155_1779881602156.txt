Ты должен создать полнофункциональное локальное веб-приложение для планирования и распределения нарядов в организации (закрытая внутренняя система, гос-стиль).

========================
📌 ОБЩИЕ ТРЕБОВАНИЯ
========================

Система работает только локально (intranet), без интернета и без внешних API.

Технологии:
- Python 3.11
- FastAPI
- Jinja2 (без React)
- SQLite (по умолчанию)
- HTML + CSS (минималистичный стиль)
- Vanilla JavaScript (минимально)

Запуск:
uvicorn app.main:app --reload

========================
🧠 ЛОГИКА СИСТЕМЫ
========================

1. ВРЕМЯ И СУТКИ

- Служебные сутки: с 20:00 до 20:00
- Астрономические сутки: с 00:00 до 00:00

Ограничения:
- не более 8 часов службы в календарные сутки
- минимум 4 часа отдыха перед следующим нарядом
- допускаются пересечения суток (например 20:00–08:00)

------------------------

2. СТАТУСЫ СОТРУДНИКОВ

- available
- sick
- vacation
- business_trip
- rest
- restricted (может ходить только в один тип наряда)
- exempt (не ходит в наряды)

------------------------

3. ТИПЫ СОТРУДНИКОВ

- contract
- conscript
- exempt

------------------------

4. НАРЯДЫ

Создаются командиром:

Поля:
- название
- тип (обязательный / дополнительный)
- время начала
- время окончания
- минимальное количество людей

------------------------

5. ОБЯЗАТЕЛЬНЫЕ НОРМЫ

Админ задаёт:
- обязательные наряды в сутки
- дополнительные наряды
- минимальный состав на каждый тип

------------------------

6. АВТОРАСПРЕДЕЛЕНИЕ (КЛЮЧЕВОЕ)

Система обязана:
- исключать sick/vacation/business_trip/rest
- учитывать лимит 8 часов в сутки
- учитывать 4 часа отдыха
- учитывать restricted (ограниченные типы нарядов)
- равномерно распределять нагрузку
- закрывать обязательные наряды в первую очередь

------------------------

7. ВЫХОДНЫЕ

- минимум 1 выходной в неделю
- минимум 6 выходных в месяц (кроме срочников)

Если сотрудник не в наряде → он обязан получить:
- activity (занятие)
- или rest (выходной)

------------------------

8. АЛЬТЕРНАТИВНАЯ ЗАНЯТОСТЬ

Если нет наряда:
- обучение
- хозяйственные работы
- административные задачи

========================
🗄️ БАЗА ДАННЫХ (SQLite)
========================

Создать таблицы:

- staff
- staff_status
- duties
- duty_types
- duty_assignments
- activities
- daily_plan
- duty_rules

========================
🖥️ ИНТЕРФЕЙС (МИНИМАЛИЗМ / ГОС СТИЛЬ)
========================

Стиль:
- без анимаций
- без закруглений
- серо-белая палитра
- таблицы вместо карточек
- плотная компоновка
- системный шрифт Arial
- без лишних визуальных элементов

------------------------

Страницы:

1. DASHBOARD
- обязательные наряды
- дополнительные наряды
- свободные сотрудники
- недоборы

2. STAFF
- таблица сотрудников
- статус
- ограничения
- нагрузка

3. DUTIES
- список нарядов
- назначения
- статус выполнения

4. SETTINGS
- нормы нарядов
- минимальный состав
- правила распределения

5. DAILY PLAN
- кто чем занят:
  duty / activity / rest

========================
⚙️ API
========================

- POST /staff
- POST /duties
- POST /generate_schedule
- GET /schedule/day/{date}
- POST /staff/status

========================
🧠 SCHEDULER ENGINE (ОБЯЗАТЕЛЬНО)
========================

Создай модуль scheduler/engine.py который:

- строит график автоматически
- проверяет все ограничения
- распределяет сотрудников
- учитывает статус каждого человека
- заполняет свободные дни activity
- гарантирует соблюдение всех правил

- запускаться локально
- не требовать интернета
- работать в закрытой сети
- быть готовой к использованию
